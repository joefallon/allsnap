## Purpose and stack

allSnap is a native Windows tray utility that changes how other applications' windows move and resize. It snaps to other windows and monitor work areas, with optional center/grid guides, a center-resize modifier, MDI handling, cropping adjustments, and class-based exclusions (`src/app/snap_App.c`, `src/engine/SNAP_LIB.H`, `src/engine/Snapper.c`, `src/engine/snap_WinRects.c`). The UI provides Preferences, Snap to grid, and Advanced property pages (`src/app/snap_settings.c`). App sound functionality has been removed.

The implementation is procedural C using Win32, common controls, resources, and Windows hooks. There is no web application, database, or package-manager dependency tree. The current solution is `allsnap.sln`, containing the `allsnap` executable (`allsnap.vcxproj`), `snap_lib` DLL (`snap_lib.vcxproj`), native Microsoft tests (`tests/allsnap_tests.vcxproj`), and two test-only process-fixture projects under `tests/process/`. They target Visual Studio 2022 (`v143`) and the latest installed Windows 10/11 SDK (`10.0`). `LICENSE` is MIT.

## Execution and architectural boundaries

1. `_tWinMain` in `src/app/snap_App.c` checks character-set support and named mutexes, registers a window class, and creates a hidden main window. Mutex/window names differ for 32-bit and 64-bit builds. Starting another instance of the same variant can unhide the existing tray icon.
2. Startup checks `SnapHookAll(hwnd, os)`, then loads INI settings and adds the tray icon. There is no audio worker or worker identifier in the hook API. Hook failure reports an error and unwinds initialization. The application runs a Win32 message loop and hosts modeless settings/about/debug windows; message-loop failure is logged. Explicit exit stays open if hook removal fails; successful shutdown removes the hook. Rebuild/copy matching EXE and DLL pairs because the old hook signature included a removed audio-thread argument.
3. `SnapHookAll` in `src/engine/snap_lib.c` installs a global `WH_CALLWNDPROC` hook. On eligible `WM_ENTERSIZEMOVE` messages, it subclasses the target window with `SetWindowSubclass`. The subclass handles `WM_MOVING` and `WM_SIZING`, invoking `src/engine/Snapper.c` to adjust the proposed `RECT` before normal message processing continues. Hook/subclass teardown and `SnapCanUnHook` govern safe exit.
4. `src/engine/snap_WinRects.c` snapshots eligible window rectangles, monitor work areas, and configured guide candidates at move/resize entry. Work-area accounting is separate from guide capacity. Top-level and MDI destinations share visibility, minimization, ignored-class, and visible-crop rules; class matching retrieves complete native names. MDI client bounds and its grid guides use desktop coordinates. Grid controls work independently of Desktop edge snapping; a SINGLE offset of zero is a valid unpadded boundary guide, while EVEN zero generates no guides. `src/engine/snap_testers.c` evaluates inclusive threshold matches; `src/engine/Snapper.c` combines these with visible-frame cropping, held modifier keys, and move/resize tracking. `src/engine/snap_KeepToScreen.c` and `src/engine/snap_InTests.c` validate the full proposed rectangle against the work-area union, preserving open internal seams and rejecting gaps or holes.

The executable imports the DLL API in `src/engine/SNAP_LIB.H`; settings setters/getters are the UI-to-engine boundary. Settings, application HWND, stopping state, and 64 registration-owner records occupy writable shared PE sections named `Shared32` or `Shared64` (`src/engine/snap_lib.c`). The installing host owns its process-local hook handle; each injected process owns its local subclass HWND/thread. Atomic generation-tagged claims reserve admission before native subclass installation; published records contain full process/thread creation identities. Shutdown discards only confirmed dead or replaced owners, retaining live or uncertain records. Exact-token cleanup cannot clear a reused slot. Host restart preserves live registrations. Process detach performs only local writes and atomic release, without probing, waiting, or User32 calls under loader lock.

Host, hook, and subclass entry pin the engine DLL with `GetModuleHandleEx(PIN | FROM_ADDRESS)` before admitting native callbacks. It remains mapped until that process exits, including after ordinary reference release or hook removal; replacing a loaded binary may require closing affected applications or building to a different path. The existing one-active-subclass-per-process geometry restriction is preserved. `src/engine/snap_TrackResults.c` retains the last result needed for continued move/resize geometry; audio transition posts, speed-based suppression, and the exclusive MouseSpeed module are removed.

## Configuration, persistence, and local integrations

- `src/app/snap_ini.c` maps `[settings]` entries to DLL/UI setters and getters. It resolves and caches `allsnap.ini` relative to **the process working directory**, not the executable directory or user profile. Launch location therefore affects settings selection and write permissions.
- Startup calls `LoadSettingsFromINI`; opening Settings calls `LoadSettingsForDialog`, which reloads other preferences without changing live enabled/icon-hidden state, even transiently. Property-page Apply/OK handlers save the INI (`src/app/snap_App.c`, `src/app/snap_settings.c`). General shutdown does not save preferences. Missing entries preserve current/default values; explicit empty ignored/skinned lists clear them. Numeric loading requires complete, nonoverflowing tokens, retaining decimal and legacy 0x syntax; booleans are normalized. Invalid persisted thresholds outside 2–100 are ignored. Preserve existing spellings such as `win_tresh` and `screen_tresh`.
- `src/app/snap_registry.c` remains in the project with `IH_USE_REGISTRY`-guarded persistence under `HKCU\Software\IvanHeckman\allSnap\Settings`, but the application does not call it at startup/shutdown. Registry settings are not the current startup source.
- Preferences now include one spacing value (0–1000 physical pixels, default 0), persisted as `window_spacing`; adjacent windows use the value once, while center/grid guides remain unpadded. The enable checkbox also persists as `enabled`. Legacy INI files without these keys retain defaults. Moving/resizing uses DWM visible bounds intersected with explicit regions; manual top crop is an absolute minimum. Physical/logical conversion rounds to representable caller coordinates at fractional scales. The user approved retaining Windows compatibility DPI scaling for the UI; geometry conversions remain explicit in the engine.
- The native Settings sheet validates active Grid modes (EVEN 0–100; PIXELS 1–INT_MAX; SINGLE 0–INT_MAX) and enabled manual crop (0–INT_MAX). Disabling a grid axis retains its mode/value; ineffective unselected edits do not block Apply. Manual crop is limited per window to retain at least one visible row without changing the saved value. Ignored/skinned semicolon lists and center/equal keys remain INI-only settings; ignored classes exclude destinations, while skinned classes bypass only manual top crop. List storage remains bounded at 399 characters.
- Apply saves keys sequentially and does not provide atomic rollback: save failure can leave edited runtime values or earlier writes in place. Native failure/retry coverage establishes error handling, not transaction semantics.
- INI persistence separates per-setting dispatch from traversal: `SaveSettingToINI` serializes one entry; `LoadSettingFromINI` applies one supported entry. Drivers retain path lookup, order, live enabled/icon-hidden preservation, and original success/failure behavior. Missing/invalid load values are skipped; unsupported types stop traversal without changing valid-path load success. Save conversions and partial writes remain unchanged. Numeric conversion uses `ParseIntegerValue` after `getInt` performs the original profile read/length guard; grammar, validation rules, and path caching are unchanged.
- Hook/subclass failures post messages to the application thread, which logs captured error codes to `%LOCALAPPDATA%\allSnap\diagnostics32.log` or `diagnostics64.log`. Hook callbacks do not write logs synchronously. Startup hook failure is reported; failed explicit unhook keeps the application open.
- Old `play_sounds`, `snap_sound_file`, and `unsnap_sound_file` INI keys are ignored; current saves do not create or rewrite them. Existing unknown/obsolete keys may remain untouched, while non-audio preferences are preserved. The checked-in INI no longer contains audio defaults. DLL defaults remain in `src/engine/snap_lib.c`.
- Sound UI/preview/playback code, worker/messages, noisy-setting exports, exclusive media assets, and WinMM linkage are removed. Current and historical project definitions and installer source lists no longer reference the retired files. Shared dialog/help libraries remain because they have other consumers.
- Help sources are under `help/`; `help/snapTo.hhp` targets root `allSnap.chm` through `..\allSnap.chm`. The checked-in historical compiled help is `legacy/archive/snapTo.chm`. The application Help command still opens `allSnap.chm`. Debug builds link the SDK's `htmlhelp.lib` for contextual popup help; Release configurations retain `NOHTMLHELP`, disabling those popups (`src/app/snap_tips.c`).

## Consequential constraints and gaps

- `resources/snapit.rc` embeds the checked-in, architecture-neutral `resources/allSnap.exe.manifest`, enabling common controls v6 and running as the invoking user. The executable linker does not generate a second manifest. The DLL resource uses SDK headers rather than the old MFC-only `afxres.h`.
- Optional auto-lineup remains disabled/unbuilt with its plugin header/source absent. Its guarded call now references the existing host thread rather than the deleted audio worker; this unsupported integration has not been validated. Root `.lib`/`.exp` artifacts do not supply the missing source/header setup.
- Inno Setup scripts (`packaging/allSnap.iss`, `packaging/allSnapDebug.iss`, `packaging/snapTo.iss`) retain older output names/layouts and packaging dependencies, including auto-lineup/help artifacts. They are not established packaging instructions for the current Unicode outputs.
- Hooked code runs in other applications, and exit can be blocked while subclassing is active (`src/engine/snap_lib.c`, `src/app/snap_App.c`). The older `help/knownproblems.html` documents custom move/size incompatibilities and DLL unloading issues; these are historical documented limitations, not newly reproduced failures.
- The current hook/subclass design uses separate x86 and x64 executables/DLLs for the two application architectures. No launcher coordinates them; each variant has its own tray window, settings state, and hook lifecycle (`src/app/snap_App.c`, `src/engine/snap_lib.c`).
- Equal-size/aspect-ratio handling remains disabled by the absent `SIZINGTOGGLE_ENABLED` build flag. Auto-lineup remains hidden/disabled. Functional Settings tests do not establish context-help rendering, focus/tab order, host tray-menu dispatch, or actual Explorer behavior.
- Candidate storage is bounded by fixed arrays in `src/engine/snap_WinRects.c`: ten work areas and one hundred additional guides. Changes to enumeration or guide generation must respect those limits. The source also retains Win9x/XP-era platform branches (`src/common/StdAfx.h`, `src/app/snap_App.c`). Automated geometry and both-architecture coverage do not establish compatibility with every modern application window.
- Lifecycle ownership is bounded at 64 records and refuses new admission on exhaustion. Unknown owner access keeps shutdown busy. If an owner dies before identity publication and its thread ID is already reused, recovery remains conservative until death can be proved; published identities guard ID reuse with full creation times. Pinned DLLs cannot be unloaded for replacement while affected processes remain alive. Real global-hook/desktop validation remains necessary.
- An original center outside the desktop can make centered full-fit confinement impossible. Real mixed-DPI/100% hardware checks and a long-running desktop trial remain pending.
